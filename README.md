# CelestiFrame

CelestiFrame（セレスティフレーム）は、指定した場所・日時における太陽・月・星景対象の位置を地図上で確認し、風景や建造物と組み合わせた写真の撮影計画を立てるためのPWAです。

## 現在の開発段階

Version 1.9.0として、最大5対象の天体選択、主対象の指定、天の川の扇表示、撮影地点逆引き、地形遮蔽、現地撮影モード、高さの簡易測定、任意ログインのクラウド同期を提供しています。選択済みチップで主対象を切り替えると、その方向だけを少し強調します。他の対象の濃さは維持します。保存計画から現地撮影へ進む導線と、現地用データのオフライン準備を追加しています。

## 予報雲レイヤー

左上の「星景条件」から、選択中の撮影日時における雲予報を地図に重ねられます。総雲・低層・中層・高層を切り替え、撮影地点の視程、風、降水確率、気温、相対湿度、露点、気温−露点差を確認できます。雲レイヤーを非表示にしても地点予報を取得できます。予報はOpen-Meteoの提供値で、48時間前から16日先までが対象です。欠測値は「—」のまま表示します。

月高度・月照明率・主対象との角距離は端末内で計算します。天の川を主対象とした角距離は銀河中心が基準です。主対象が月自身なら角距離は「—」です。照明率は月面の明るい部分の割合で、地上の照度ではありません。

グリッド予報は局地的な雲、地形性の雲、短時間の変化を正確に示すものではありません。最終的な出発判断には、現地の実況・衛星画像・気象警報も確認してください。

## 光害の目安レイヤー

左上の「光害」スイッチから、NASA VIIRSのVNP46A4 2025年次夜間光を日本周辺の地図へ重ねられます。雪のない期間の全観測角度合成を使用し、明るい場所ほど人工光が強い傾向を示します。暗い撮影地を探すための広域的な目安として使えます。

これは空の明るさ、ボートル階級、透明度を直接示すデータではありません。2025年の地表夜間光を使った参考表示であり、地形による遮光、撮影当日の雲・大気、月明かりは反映しません。データ表示には`NASA VIIRS / VNP46A4`の帰属とDOIを付けています。

### VNP46A4タイルの更新

元HDF5はGit管理せず、`data/vnp46a4-source/`へ保存します。NASA Earthdataのダウンロードトークンを一時環境変数`EARTHDATA_TOKEN`へ設定してから、次を実行します。トークンをファイルやシェル履歴へ残さないでください。

```powershell
py -3 -m pip install -r tools/requirements-vnp46a4.txt
py -3 tools/generate-vnp46a4-tiles.py
Remove-Item Env:EARTHDATA_TOKEN
```

対象年・日本周辺を覆うLAADSファイルは`tools/vnp46a4-2025-japan.json`で固定し、生成物は`assets/light-pollution/vnp46a4-2025/`へ出力します。

## Version 1.1の撮影支援

撮影地点候補は、被写体から見た天体方位の反対方向へ1・5・10・20kmの地点を示します。候補地点が道路上か、水上・私有地・立入禁止区域ではないかは自動判定しないため、地図と現地情報を確認してください。

地形断面は撮影地点と被写体の間を21点に分け、国土地理院DEMの標高と地球曲率から見通しを推定します。建物、樹木、造成、積雪、局地的な大気差は含みません。

天の川表示はIAUの銀河座標系に基づく銀河面を使い、地図には地平線より上の方位範囲を半透明の扇で表示します。中心周辺（銀経0°から±45°）は中心に近いほど濃くする模式表示で、実測の明るさ分布ではありません。地平線下の部分は描画せず、中心が沈んでいても周辺の一部が昇っていれば、その部分の濃淡は残します。銀河中心の細線と点は中心が地平線上にある場合だけ表示します。

撮影地点を基準にした扇は塗りつぶし、被写体地点を基準にした扇は破線の外周で区別します。扇の半径は地図の倍率に合わせた表示上の大きさで、天体までの距離や高度は表しません。高度はカード内のアーチ図で確認できます。最高点の方位・高度、日時検索、撮影地点逆引きは引き続き10°間隔で求めたアーチ最高点を基準にします。表示は幾何学的な方向であり、光害、月明かり、雲、透明度、地形による遮蔽を含めた見えやすさは判定しません。

現地撮影モードは、撮影地点へ到着するまでは撮影地点を案内し、30m以内では被写体方向へ切り替えます。端末方位は磁気センサーの影響を受けるため目安として使用してください。

## ローカル起動

Service Workerと位置情報を正しく扱うため、ファイルを直接開かずローカルHTTPサーバーを使用してください。

```powershell
npm run serve
```

表示されたローカルURLをブラウザで開きます。


## テスト

```powershell
npm test
```

UI回帰は `node tools/verify-browser.mjs` で検証できます（PlaywrightとChromeが必要）。`QA_URL` は検証先、`QA_OUTPUT` は画面・結果の保存先を指定します。320px・390px・PC、各テーマ、単一／複数対象、保存・再読込、地形・予報の遅延応答、オフライン起動を確認します。CPUを4倍に制限した計測はJavaScript処理時間で、画面描画全体や実機の操作遅延を表すものではありません。

天の川の描画回帰は `node tools/verify-milkyway.mjs` で検証できます。同じ環境変数を使い、中心の出没、中心周辺だけが昇った状態、北をまたぐ方位、南半球、天頂付近、各基準地点、テーマ・画面幅・地図倍率の変更と表示解除を確認します。

Firestoreは `firebase.emulator.json` と `tools/verify-firestore.mjs` で、所有者の分離・1000mと未取得標高の保存・削除と古い更新の競合を検証します。準備はスクリプト冒頭を参照してください。エミュレーター専用の `demo-celestiframe` を使用し、本番データを試験には使いません。

公開時は `package.json`・ロックファイル・表示バージョンを揃え、`node tools/version-assets.mjs` でモジュールとCSSのURLを統一します。UIの文字を追加した場合は、fonttoolsとbrotliを用意して `python tools/subset-fonts.py` でフォントを再生成します。元の日本語フォントとOFLライセンスは保持し、追加の地名・計画名に必要な文字を補います。

## データとオフライン動作

撮影地点、日時、表示対象などの初期設定は端末内へ保存します。初回オンライン表示後はアプリシェルをキャッシュし、オフラインでも時刻変更や天体計算を利用できます。地図や予報の更新には通信が必要です。ブラウザーに残った地図が表示される場合もありますが、地図のオフライン利用は保証しません。

保存計画の「…」→「この計画をオフライン準備」で、標高、被写体までの地形断面、撮影時刻の地点予報、同梱のVNP46A4光害タイルを端末内の別IndexedDB `celestiframe-offline-v1` に保持します。計画一覧・詳細に準備状態、項目ごとの出典と取得日時、取得できなかった理由を表示します。保存済みデータは計画を開くと復元され、予報は「保存値」と取得日時を表示します。地点・日時等が違う計画には流用しません。現地用データはJSON書出し・共有・クラウド同期に含めません。

光害は撮影・被写体地点周辺の最大36タイル（保存時の縮尺とネイティブズーム8）に限定します。復元時に有効計画のタイルだけを `celestiframe-field-light-v1` キャッシュへ展開します。背景地図、検索結果、雲の面レイヤーは保存しません。OSM標準タイルの事前取得は[公式利用方針](https://operations.osmfoundation.org/policies/tiles/)に従い行いません。独自の光害提供元は自動で保存対象にしません。端末のサイトデータを削除すると現地用データも消えます。

同じ「…」の「この計画で現地撮影」は計画を復元して現地モードを開きます。GPS・方位センサーとWake Lockは画面内の各開始ボタンから利用します。

追加回帰確認は `node tools/verify-primary-target.mjs` と `node tools/verify-field-plans.mjs` です。後者はAPIを固定応答にして、準備→通信遮断→再読込→復元→現地モード、地点予報の誤流用防止、各幅・テーマを検証します。実端末のセンサー精度や実予報の正しさを保証するテストではありません。

1.7.0のクラウド同期は、削除記録を計画と同じトランザクションで保存します。`firestore.rules` も同時に公開してください。古いクライアントからの削除は新ルールに拒否されるため、更新後のクライアントで再同期します。端末内への保存は通信完了を待たず、同期状態は計画画面で確認できます。以前の版で誤って確定済みの0mとして保存された標高は、真の0mと区別できないため自動修復しません。

## 場所検索とNominatim利用上の制限

場所検索にはOpenStreetMap Foundationが運用する公開Nominatim APIを使用します。公開サービスの負荷を抑えるため、入力中の自動補完は行わず、ユーザーが検索を実行した場合だけ通信します。同一検索語の結果は端末内へ7日間保存し、最大1リクエスト/秒を守ります。検索結果にはOpenStreetMapの帰属表示を付けています。

公開Nominatim APIには利用量と用途の制限があり、大規模利用・一括検索・自動補完には使用できません。利用規模が増えた場合は、`config/runtime-config.json`の`nominatimEndpoint`をセルフホストまたは別の提供事業者へ切り替えてください。アプリ本体の再ビルドは不要です。詳細は[Nominatim Usage Policy](https://operations.osmfoundation.org/policies/nominatim/)を確認してください。

## 外部サービスの実行時設定

場所検索、地図タイル、光害の目安タイル、天気予報の接続先は`config/runtime-config.json`で変更できます。

```json
{
  "nominatimEndpoint": "https://nominatim.openstreetmap.org/search",
  "tileUrl": "https://tile.openstreetmap.org/{z}/{x}/{y}.png",
  "lightPollutionTileUrl": "./assets/light-pollution/vnp46a4-2025/{z}/{x}/{y}.webp",
  "lightPollutionDataYear": 2025,
  "weatherForecastEndpoint": "https://api.open-meteo.com/v1/forecast"
}
```

外部接続先はHTTPSのみ許可します。光害タイルは`assets`配下の同一オリジン相対パスも許可します。タイルURLには`{z}`、`{x}`、`{y}`が必要です。不正な設定や取得失敗時は安全な既定値へ戻ります。OpenStreetMap標準タイルを使う場合は、[Tile Usage Policy](https://operations.osmfoundation.org/policies/tiles/)に従い、URLや帰属表示を維持してください。

## セキュリティとプライバシー

- 入力内容を生成AIやLLMへ送信する処理はありません。検索語は設定された場所検索サービスにだけ送信されます。
- 画面へ表示する検索結果、計画名、メモ、共有URLの被写体名はテキストとして描画し、HTMLとして実行しません。
- 場所検索は120文字、計画JSONは5MBかつ1000件までに制限しています。
- Content Security Policyを設定し、Leafletの外部ファイルはバージョン固定とSubresource Integrityで検証します。
- 撮影地点、被写体地点、日時、計画は端末内へ保存されます。共有URLには地点・日時・被写体名が含まれるため、公開範囲に注意してください。

## 標高データとダイヤモンド判定

地点を確定した時だけ国土地理院の標高APIへ問い合わせ、利用可能な中で最も高精度な数値標高モデルの値を取得します。取得値は地表面の推定標高であり、建物・樹木・積雪を含みません。建造物を狙う場合は「建造物」を選び、地表から照準点までの高さを入力してください。

ダイヤモンド判定は、撮影地点と照準点の標高、距離、地球曲率、標準的な大気差、太陽円盤の角半径を使った撮影計画上の推定です。実際の大気状態、地形による途中遮蔽、雲や視界は判定しません。標高APIの仕様と注意事項は[国土地理院の技術情報](https://maps.gsi.go.jp/development/elevation_s.html)を確認してください。

## 注意

CelestiFrameが今後表示する天体位置や重なり予測は、写真撮影計画のための計算上の目安です。測量用途には使用できません。重要な撮影では現地確認を行ってください。
